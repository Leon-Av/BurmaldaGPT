# Дизайн-документ: БурмалдаGPT

**Дата:** 2026-07-25
**Статус:** реализовано

## Цель

Построить профессиональный многопользовательский чат с LLM, в котором ответы модели переводятся на «бурмалду» (муринский язык) и стримятся пользователю. Полный аналог ChatGPT по UX.

## Архитектура

Трёхзвенка:
1. **Frontend** (React+Vite+TS) — UI, авторизация, стриминг-клиент.
2. **Backend** (FastAPI+SQLite) — аккаунты, чаты, конвейер LLM→перевод→стрим.
3. **Burmalda API** (существующий переводчик) — `POST /translate`.

LLM (OpenAI-compatible сервер, адрес и модель настраиваются в `backend/config.yaml`) отделена от переводчика.

## Ключевые решения

- **Движок**: реальная LLM, ответ переводится через `/translate` (детерминированно, связно).
- **Конвейер стриминга «по предложениям»**: буфер токенов до границы предложения → перевод → SSE-delta клиенту. Баланс живости и качества перевода. Плюс time-based flush (1.5 c) для буферов без знаков препинания.
- **Аккаунты**: свой backend, JWT (7 дней), bcrypt. Многопользовательский.
- **БД**: SQLite (переключается на Postgres через `DATABASE_URL`).
- **Стек**: React+Vite+TS+Tailwind+Framer Motion / FastAPI+SQLAlchemy.
- **Мультимодал**: до 5 изображений, переключается `vision_enabled` в конфиге.
- **Параллельность**: `asyncio.Semaphore(max_concurrent)` вокруг запросов к LLM.

## Устойчивость

- Обрыв LLM-соединения без `[DONE]` (vLLM/llama.cpp) трактуется как нормальное завершение, если получен хотя бы один токен.
- При ошибке/обрыве накопленный перевод всё равно сохраняется в БД.
- Переводчик при ошибке возвращает оригинал (деградация без прерывания стрима).
